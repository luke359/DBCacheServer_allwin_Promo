| Host | 主程式 | 載入核心服務的 DBCache；負責身份、錢包、遊戲資料及外部流程 |

| Promotion Activity | 優惠活動設定 | H5gSet 建立或更新、由核心服務讀取的活動規則 |

| Promotion Trigger Event | 優惠觸發事件 | Host 以全域唯一 EventId 通知核心服務建立資格的事件及其首次處理事實 |
| Bonus Status | 玩家優惠活動總狀態 | 每位玩家唯一且永久保留的總狀態，包含目前進行中的 Bonus Task |
| Eligibility Entry | 可領活動項目 | 某事件為玩家與活動建立、只在原 Business Day 有效的領取資格 |
| Bonus History | 活動歷史紀錄 | Bonus Task 結案後建立並保存 90 日的不可變紀錄 |
| Required Wager Amount | 目標流水量 | 完成 Bonus Task 所需累計的有效投注額 |
| Current Wager Amount | 已累計流水量 | Bonus Task 已累計的有效投注額 |

| Business Day | 活動日 | 從 Host 傳入的每日切換時間起，至下一次切換時間前的活動週期 |
| Exclusive Group | 優惠互斥群組 | 同一群組內只能成功領取一個優惠的集合 |
| Idempotency | 冪等性 | 同一業務要求重複執行時，不重複產生狀態異動，並可重現首次結果 |
| Transaction | 交易 | 一組必須全部成功或全部回復的資料庫操作 |
| Row Lock | 資料列鎖 | 由 MySQL 提供、可跨程序序列化同一玩家異動的鎖定機制 |

## 5. 共通資料規則

### 5.1 命名與時間

- C# 型別、屬性、方法、資料表及欄位一律使用 Pascal Case(帕斯卡命名法)。
- `BusinessDay` 只表示活動日日期，C# 使用 `DateOnly`，MySQL 使用 `DATE`。
- `EventTime`、`CreatedAt`、`UpdatedAt`、`ClaimedAt`、`ClosedAt` 及 `StatusChangedAt` 使用系統本地時間；C# 使用 `DateTime`，MySQL 使用 `DATETIME(6)`。
- 資料庫時間值固定以 `yyyy-MM-dd HH:mm:ss.ffffff` 和 `CultureInfo.InvariantCulture` 轉換。
- 核心服務不得以資料庫伺服器時區重新推導 `BusinessDay`；一律使用 Host 初始化時提供的切換時間計算。

### 5.2 金額與精度

- 整數活動設定在 C# 使用 `int` 或 `int?`，MySQL 使用 `INT`：`FixedBonusAmount`、`MaxBonusAmount`、`DepositPercentage`、`MinimumDepositAmount`、`WagerMultiplier`、`MaxBetAmount`、`FixedConvertedAmount`、`MaxBalanceConvertedAmount`、`DailyClaimLimit`。
- 小數活動設定 `WagerContributionRate` 在 C# 使用 `decimal`，MySQL 使用 `DECIMAL(20,4)`。
- 實際任務金額、流水、計算結果及公式中間值在 C# 使用 `decimal`，MySQL 儲存欄位使用 `DECIMAL(20,4)`。
- 需要限制精度的計算結果直接截斷至小數第 4 位，不得四捨五入。
- `RemainingWagerAmount` 為衍生值，不寫入資料庫，以避免和 `RequiredWagerAmount`、`CurrentWagerAmount` 不一致。
- `MaxBetAmount` 與 `MaxBalanceConvertedAmount` 在 C# 使用 `int?`、MySQL 使用可為空的 `INT`；`null` 表示無限制，有值時仍須符合原範圍。
- 百分比設定保存顯示值，例如整數 `DepositPercentage = 30` 與小數 `WagerContributionRate = 30.0000` 都代表 30%，計算時使用 `decimal` 除法除以 100。

### 5.3 識別碼

- `UserUID` 與 `ActivityUID` 在 C# 使用 `long`，MySQL 使用 `BIGINT`；`UserUID` 的實體型別與正負號必須和既有玩家主檔一致。
- `BonusTaskId` 由核心服務以 `Guid.NewGuid().ToString("D")` 產生，固定為 36 個 ASCII 字元。
- `EventId` 由 Host 產生且全域唯一，第一版限制為 1～128 個字元；核心服務視為不透明字串，不解析其內容。
- 所有識別碼進入核心服務後不得被截斷、轉換大小寫或移除空白；Host 不得傳入前後空白。

### 5.4 空值與不可變資料

- 表格中的「可為空」代表 C# nullable 型別及 MySQL `NULL`，不以 `0`、空字串或特殊日期代替。
- `ActivitySnapshotJson` 是 UTF-8 JSON 文字；序列化欄位名稱及列舉數值必須符合第 8 節。
- Bonus Task 建立後，其 `ActivitySnapshotJson` 不得更新。
- Bonus History 建立後不可更新；只有超過 90 日的清理流程可以刪除。

## 6. 共用識別碼與列舉

所有列舉在 C# 使用具名 `byte enum`，在 MySQL 使用 `TINYINT UNSIGNED`。資料庫只保存數值，不保存列舉名稱。

### 6.1 BonusType

| 值 | 名稱 | 說明 |
|---:|---|---|
| 1 | FixedAmount | 固定金額 Bonus |
| 2 | DepositPercentage | 以合格儲值金額百分比計算 Bonus |

### 6.2 TriggerType

| 值 | 名稱 | 說明 |
|---:|---|---|
| 1 | Registration | 註冊 |
| 2 | FirstLoginOfBusinessDay | 每日首登入 |
| 3 | FirstDepositOfBusinessDay | 每日首儲 |
| 4 | Deposit | 儲值 |
| 5 | Free | 免費活動 |

### 6.3 ConvertType

| 值 | 名稱 | 說明 |
|---:|---|---|
| 1 | Fixed | Fixed Convert |
| 2 | Balance | Balance Convert |

### 6.3.1 WagerCalculationType

| 值 | 名稱 | 目標流水計算方式 |
|---:|---|---|
| 1 | BonusOnly | `BonusAmount × WagerMultiplier` |
| 2 | DepositAndBonus | `(EligibleDepositAmount + BonusAmount) × WagerMultiplier`；沒有儲金時以 0 計 |

### 6.4 EligibilityStatus

| 值 | 名稱 | 說明 |
|---:|---|---|
| 1 | Available | 可領取 |
| 2 | Claimed | 已領取 |
| 3 | Excluded | 已排除 |
| 4 | Expired | 已逾期 |

合法轉換只有：`Available → Claimed`、`Available → Excluded`、`Available → Expired`。終態不得再轉換。

### 6.5 BonusTaskState

| 值 | 名稱 | 說明 |
|---:|---|---|
| 0 | None | 無進行中任務 |
| 1 | InProgress | 進行中 |
| 2 | Closing | 結案處理中，只能存在於尚未提交的結案交易內 |

`Closing` 不得作為已提交後長期停留的狀態。結案交易成功時直接重置為 `None`；失敗或公式例外時回復為 `InProgress`。

### 6.6 CloseReason

| 值 | 名稱 | ConvertedAmount |
|---:|---|---:|
| 1 | WagerCompleted | 依 ConvertType 計算 |
| 2 | BonusDepleted | 0 |
| 3 | PlayerAbandoned | 0 |
| 4 | BusinessDayExpired | 0 |

## 7. Promotion Activity 欄位

Promotion Activity 是可變的目前設定。H5gSet 可更新設定，但不得直接覆寫既有 Bonus Status 或 Bonus History 的 Activity Snapshot。

| 欄位 | C# 型別 | 可為空 | 規則 |
|---|---|---:|---|
| ActivityUID | `long` | 否 | 活動唯一識別碼，建立後不可變 |
| ActivityInfo | `string?` | 是 | 玩家顯示資訊，最長 100 字元 |
| BonusType | `BonusType` | 否 | Bonus 派發方式 |
| FixedBonusAmount | `int` | 否 | 固定金額，範圍 1～100 |
| MaxBonusAmount | `int` | 否 | 百分比 Bonus 上限，範圍 1～100 |
| DepositPercentage | `int` | 否 | 儲值百分比，範圍 1～1000 |
| MinimumDepositAmount | `int?` | 是 | 儲值門檻；免費活動為 `null` |
| WagerMultiplier | `int` | 否 | 洗碼量，範圍 1～100 |
| WagerCalculationType | `WagerCalculationType` | 否 | 目標流水計算方式，只允許 1 或 2 |
| MaxBetAmount | `int?` | 是 | 押注上限，有值時範圍 1～100；`null` 表示無限制，由 GameServer 執行 |
| GameServerList | `string?` | 是 | 優惠可玩遊戲列表，最長 500 字元；核心僅原樣提供 Host 查詢，不解析或判斷內容 |
| WagerContributionRate | `decimal` | 否 | 押注流水百分比，範圍 1.0～100.0 |
| ConvertType | `ConvertType` | 否 | 解鎖方式 |
| FixedConvertedAmount | `int` | 否 | Fixed Convert 金額，範圍 1～1000 |
| MaxBalanceConvertedAmount | `int?` | 是 | Balance Convert 上限，有值時範圍 1～1000；`null` 表示無限制 |
| DailyClaimLimit | `int` | 否 | 每位玩家每個 Business Day 的成功領取上限，範圍 1～99 |
| StartDate | `DateOnly?` | 是 | `null` 表示不限開始日期；包含本日 |
| EndDate | `DateOnly?` | 是 | `null` 表示無限期；不包含本日 |
| WeekdayMask | `string` | 否 | 7 字元、只允許 `0` 或 `1`，順序為星期一至星期日 |
| ActivityStatus | `ActivityStatus` | 否 | `Active = 1`、`Archived = 2`；封存活動不再產生新資格 |
| TriggerType | `TriggerType` | 否 | 可產生資格的事件類型 |
| IsNonStackable | `bool` | 否 | `true` 表示領取時會與其他不可疊加優惠互相排除 |
| ExclusiveGroup | `string?` | 是 | `null` 表示無群組；非空時最長 64 字元 |
| CreatedAt | `DateTime` | 否 | 建立時間 |
| UpdatedAt | `DateTime` | 否 | 最後更新時間 |

活動設定更新與資格領取的關係：

- Eligibility Entry 只保存 `ActivityUID`，不保存活動快照。
- 查詢資格時顯示目前的 Promotion Activity。
- 成功領取時，以取得玩家 Row Lock 後讀到的 Promotion Activity 建立 Activity Snapshot。
- Promotion Activity 不得實體刪除；停用時使用 `WeekdayMask = "0000000"`。如此可確保已存在的 Eligibility Entry 仍能讀取與領取。
- 封存時使用 `ActivityStatus = Archived`。封存只阻止產生新的 Eligibility Entry；封存前已建立且仍有效的資格可繼續領取。

## 8. Activity Snapshot 欄位

`ActivitySnapshotJson` 使用下列固定 JSON 物件。原版 `SnapshotVersion = 1` 的欄位與語意維持不變；本次新增 `SnapshotVersion = 2`。新版任務一律寫入版本 2；讀取既有版本 1 時，`WagerCalculationType` 視為 `BonusOnly`，兩個原本必填的上限仍為原值。`GameServerList` 僅供查詢目前活動設定，不納入任務快照。`ActivityStatus` 是目前活動的生命週期狀態，也不納入任務快照。

| JSON 欄位 | 型別 | 可為空 | 來源 |
|---|---|---:|---|
| SnapshotVersion | `int` | 否 | 既有快照為 1；新版快照為 2 |
| ActivityUID | `long` | 否 | Promotion Activity |
| ActivityInfo | `string?` | 是 | Promotion Activity |
| BonusType | `byte` | 否 | `BonusType` 數值 |
| FixedBonusAmount | `int` | 否 | Promotion Activity |
| MaxBonusAmount | `int` | 否 | Promotion Activity |
| DepositPercentage | `int` | 否 | Promotion Activity |
| MinimumDepositAmount | `int?` | 是 | Promotion Activity |
| WagerMultiplier | `int` | 否 | Promotion Activity |
| WagerCalculationType | `byte` | 否 | 版本 2 新增，Promotion Activity 的列舉數值 |
| MaxBetAmount | `int?` | 是 | 版本 2 可為 `null`；版本 1 必須為 `int` |
| WagerContributionRate | `decimal` | 否 | Promotion Activity |
| ConvertType | `byte` | 否 | `ConvertType` 數值 |
| FixedConvertedAmount | `int` | 否 | Promotion Activity |
| MaxBalanceConvertedAmount | `int?` | 是 | 版本 2 可為 `null`；版本 1 必須為 `int` |
| DailyClaimLimit | `int` | 否 | Promotion Activity |
| StartDate | `yyyy-MM-dd` 字串或 `null` | 是 | Promotion Activity |
| EndDate | `yyyy-MM-dd` 字串或 `null` | 是 | Promotion Activity |
| WeekdayMask | `string` | 否 | Promotion Activity |
| TriggerType | `byte` | 否 | `TriggerType` 數值 |
| IsNonStackable | `bool` | 否 | Promotion Activity |
| ExclusiveGroup | `string?` | 是 | Promotion Activity |
| CapturedAt | `yyyy-MM-dd HH:mm:ss.ffffff` 字串 | 否 | 領取時間 |

JSON 中的 `int` 與 `decimal` 必須寫成 JSON number，禁止寫成受地區格式影響的字串。序列化後不得包含未定義的動態業務資料。

## 9. Promotion Trigger Event 欄位

Promotion Trigger Event 保存 EventId 首次處理的輸入事實。此模型是必要的冪等性紀錄：若首次事件沒有產生任何 Eligibility Entry，仍可由事件紀錄判斷其已處理，避免重送時重新篩選活動。

| 欄位 | C# 型別 | 可為空 | 規則 |
|---|---|---:|---|
| EventId | `string` | 否 | Host 全域唯一識別碼，長度 1～128 |
| UserUID | `long` | 否 | 首次事件的玩家 |
| TriggerType | `TriggerType` | 否 | 首次事件類型 |
| EventTime | `DateTime` | 否 | Host 提供的事件時間 |
| BusinessDay | `DateOnly` | 否 | 依 EventTime 與切換時間計算 |
| EligibleDepositAmount | `decimal?` | 是 | 每日首儲或儲值事件必填；其他類型為 `null` |
| CreatedAt | `DateTime` | 否 | 首次成功處理時間 |

相同 EventId 重送時，核心服務回傳此事件關聯的既有 Eligibility Entry 清單，不重新套用活動設定。若重送內容與首次的玩家、類型、時間或合格儲值金額不同，資料仍以首次內容為準，並由 PCS-05 定義衝突錯誤。

## 10. Eligibility Entry 欄位

| 欄位 | C# 型別 | 可為空 | 規則 |
|---|---|---:|---|
| EligibilityEntryId | `long` | 否 | 資料庫產生的流水識別碼 |
| EventId | `string` | 否 | 來源 Promotion Trigger Event |
| UserUID | `long` | 否 | 資格所屬玩家 |
| ActivityUID | `long` | 否 | 資格所屬活動 |
| BusinessDay | `DateOnly` | 否 | 只在此 Business Day 有效 |
| TriggerType | `TriggerType` | 否 | 建立資格的事件類型 |
| EligibleDepositAmount | `decimal?` | 是 | 百分比 Bonus 的計算基數；非儲值事件為 `null` |
| Status | `EligibilityStatus` | 否 | 初始為 `Available` |
| ClaimedBonusTaskId | `string?` | 是 | `Claimed` 時必填，其餘狀態為 `null` |

## 11. Bonus Status 欄位

每位玩家固定一列。第一次需要時建立，之後不刪除。

| 欄位 | C# 型別 | 可為空 | 無任務時 | 規則 |
|---|---|---:|---|---|
| UserUID | `long` | 否 | 保留 | 唯一玩家識別碼及資料列鎖定目標 |
| TaskState | `BonusTaskState` | 否 | `None` | 每位玩家最多一個進行中任務 |
| BonusTaskId | `string?` | 是 | `null` | 有任務時必須為 36 字元 Guid |
| EligibilityEntryId | `long?` | 是 | `null` | 本任務來源資格 |
| ActivityUID | `long?` | 是 | `null` | 本任務活動 |
| BusinessDay | `DateOnly?` | 是 | `null` | 領取所屬 Business Day |
| LastFirstLoginBusinessDay | `DateOnly?` | 是 | 保留 | 最近一次每日首登入事件所屬 Business Day；只有較晚活動日可再次觸發 |
| LastFirstDepositBusinessDay | `DateOnly?` | 是 | 保留 | 最近一次每日首儲事件所屬 Business Day；只有較晚活動日可再次觸發，第一筆成功儲值即更新 |
| ActivitySnapshotJson | `string?` | 是 | `null` | 有任務時必填且不可更新 |
| BonusAmount | `decimal` | 否 | `0` | 實際派發 Bonus |
| RequiredWagerAmount | `decimal` | 否 | `0` | 任務目標流水 |
| CurrentWagerAmount | `decimal` | 否 | `0` | 已累計流水 |
| ClaimedAt | `DateTime?` | 是 | `null` | 成功領取時間 |
| CreatedAt | `DateTime` | 否 | 保留 | Bonus Status 首次建立時間 |
| UpdatedAt | `DateTime` | 否 | 更新 | 最後狀態更新時間 |

有任務時，所有 nullable 任務欄位必須同時非空；`BonusAmount`、`RequiredWagerAmount` 不得小於 0，`CurrentWagerAmount` 可超過目標但不得小於 0。

兩個每日觸發日期不是任務欄位，不隨任務結案或每日維護清除。建立每日首登入／首儲事件時，核心服務在玩家 Row Lock 保護下比對並更新日期；只有事件 Business Day 晚於已保存日期時才更新，避免延遲的舊日事件使日期倒退。排程延遲或失敗不影響新活動日判斷。

## 12. Bonus History 欄位

每個 BonusTaskId 最多建立一筆，建立後不可更新。

| 欄位 | C# 型別 | 可為空 | 規則 |
|---|---|---:|---|
| BonusHistoryId | `long` | 否 | 資料庫產生的流水識別碼 |
| BonusTaskId | `string` | 否 | 對應任務，全表唯一 |
| UserUID | `long` | 否 | 玩家識別碼 |
| EligibilityEntryId | `long` | 否 | 原始資格 |
| ActivityUID | `long` | 否 | 活動識別碼 |
| BusinessDay | `DateOnly` | 否 | 任務所屬 Business Day |
| ActivitySnapshotJson | `string` | 否 | 從 Bonus Status 原樣複製，不重新序列化目前活動設定 |
| BonusAmount | `decimal` | 否 | 原任務 Bonus |
| RequiredWagerAmount | `decimal` | 否 | 原任務目標流水 |
| CurrentWagerAmount | `decimal` | 否 | 結案當下已累計流水 |
| ConvertedAmount | `decimal` | 否 | 結案產生的解鎖金；非達標結案為 0 |
| CloseReason | `CloseReason` | 否 | 四種正式結案方式之一 |
| ClaimedAt | `DateTime` | 否 | 原任務成功領取時間 |
| ClosedAt | `DateTime` | 否 | 成功結案時間及 90 日保留期計算基準 |
| CreatedAt | `DateTime` | 否 | 歷史列建立時間，通常等於 ClosedAt |

`ClosedAt < 清理執行時間 - 90 日` 的紀錄可由每日維護刪除；等於界線的紀錄不提前刪除。

## 13. 衍生欄位與計算規則

| 欄位 | 是否儲存 | 計算 |
|---|---:|---|
| RemainingWagerAmount | 否 | `Max(RequiredWagerAmount - CurrentWagerAmount, 0)` |
| 原始百分比 Bonus | 否 | `EligibleDepositAmount × DepositPercentage ÷ 100` |
| BonusAmount | 是 | `Min(截斷至 4 位的原始百分比 Bonus, MaxBonusAmount)`；固定型使用 FixedBonusAmount |
| RequiredWagerAmount | 是 | `WagerCalculationType = 1`：`截斷至 4 位(BonusAmount × WagerMultiplier)`；`WagerCalculationType = 2`：`截斷至 4 位((Coalesce(EligibleDepositAmount, 0) + BonusAmount) × WagerMultiplier)` |
| 本局有效流水 | 否 | `截斷至 4 位(本局押注 × WagerContributionRate ÷ 100)` |
| ConvertedAmount | History 儲存 | Fixed 使用 FixedConvertedAmount；Balance 使用外部公式結果截斷後，有上限時與上限取小值，`MaxBalanceConvertedAmount = null` 時不設上限 |

所有計算使用 Bonus Status 中的 Activity Snapshot，不讀取更新後的 Promotion Activity。

## 14. Bonus Status 重置規則

結案交易必須先建立 Bonus History，再依下表重置 Bonus Status。

| 欄位 | 結案後處理 |
|---|---|
| UserUID | 保留 |
| TaskState | 設為 `None` |
| BonusTaskId | 設為 `null` |
| EligibilityEntryId | 設為 `null` |
| ActivityUID | 設為 `null` |
| BusinessDay | 設為 `null` |
| LastFirstLoginBusinessDay | 保留 |
| LastFirstDepositBusinessDay | 保留 |
| ActivitySnapshotJson | 設為 `null` |
| BonusAmount | 設為 `0` |
| RequiredWagerAmount | 設為 `0` |
| CurrentWagerAmount | 設為 `0` |
| ClaimedAt | 設為 `null` |
| CreatedAt | 保留 |
| UpdatedAt | 更新為結案時間 |

若 Bonus History 寫入、外部公式或同交易的任何步驟失敗，以上重置全部不得提交。

## 15. 模型關聯

```text
PromotionTriggerEvent 1 ── 0..N EligibilityEntry N ── 1 PromotionActivity
                                      │
                                      │ 成功領取
                                      ▼
User 1 ── 1 PromotionBonusStatus（目前任務） ──結案──> 0..N PromotionBonusHistory
```

- Promotion Trigger Event 可對應零筆 Eligibility Entry，以涵蓋首次沒有符合活動的事件。
- Eligibility Entry 成功領取後，以 `ClaimedBonusTaskId` 對應 Bonus Status 或 Bonus History。
- Bonus Status 保存目前任務及玩家最近一次每日首登入／首儲的 Business Day；Bonus History 保存已結案任務。
- Promotion Activity 可更新，Activity Snapshot 則隨任務與歷史固定。
